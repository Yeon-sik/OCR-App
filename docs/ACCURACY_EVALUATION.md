# 정확도 평가 방법

이 앱은 측정 전 정확도를 주장하지 않습니다. 실제 영수증과 직접 전사한 정답 데이터는 로컬·비공개로 유지하고 Git, 앱 로그, 이슈, 채팅에 올리지 않습니다.

측정 경로는 두 가지입니다. **먼저 A를 쓰세요.** 정답을 따로 입력할 필요가 없어 표본을 빠르게 모을 수 있습니다. B는 A로 계산할 수 없는 지표(전체 텍스트 CER, 문서 경계 검출률)가 필요할 때만 씁니다.

## A. 검수 이력 기반 필드 오류율 (기본)

검수 화면에서 사용자가 고친 값은 그 자체로 "OCR이 뭐라고 읽었고 실제는 무엇이었는지"의 라벨입니다. 앱은 확정(`user_verified`)한 영수증의 `ReviewEdit` 이력에서 필드별 오류율을 자동 계산합니다. 별도 전사 작업이 없습니다.

1. 영수증을 평소처럼 촬영·검수하고 **확정까지 마칩니다.** 확정하지 않은 세션은 표본에 들어가지 않습니다.
2. 판매처·길이·조명·글꼴이 다른 표본을 10~20건 모읍니다.
3. 세션 목록 → 정확도 평가 화면에서 표를 확인하고, 필요하면 보고서를 공유합니다.

지표 정의:

- 필드 관측 수 = 그 필드를 인식했어야 하는 기회 수. 문서 필드는 확정본에 값이 있는 표본 수, 행 필드는 전체 상품 행 수입니다. OCR이 만들어낸 값(사용자가 지운 값)은 확정본에 남지 않으므로 분모에 다시 더합니다.
- 필드 오류율 = 수정된 수 / 관측 수
- 오류를 세 가지로 나눕니다. **틀리게 읽음**(값은 냈으나 다름), **못 읽음**(아무 값도 못 냄), **없는 값 생성**(인쇄되지 않은 값을 만듦). 셋은 대응이 다릅니다 — 못 읽음은 이미지 품질, 틀리게 읽음은 인식 모델, 없는 값 생성은 파서 경계 문제인 경우가 많습니다.
- 평균 수정 문자 수 = 수정된 항목의 Levenshtein 거리 평균. 한 글자 오타와 완전히 다른 문자열을 구분합니다.
- 검수 소요 시간 = OCR 초안 생성 시각부터 확정 시각까지의 **중앙값**. 평균은 한 건의 중단으로 크게 흔들리므로 중앙값을 씁니다.
- 영수증당 평균 수정 횟수

한 필드를 여러 번 고치거나 되돌린 경우는 **최초 OCR 값과 최종 확정값만 비교해 1회로 셉니다.** 되돌려서 원래 값으로 돌아왔다면 오류로 세지 않습니다.

**이 방법의 한계를 보고할 때 반드시 함께 적습니다: 사용자가 발견한 오류만 셉니다.** 못 보고 지나친 오류는 정답으로 집계되므로 결과는 실제 오류율의 하한입니다. 특히 주소처럼 사용자가 대충 확인하고 넘기기 쉬운 필드는 과소평가됩니다.

보고서 파일에는 건수와 비율만 들어가며 판매처명·주소·상품명과 OCR 원문은 포함되지 않습니다. 그래서 보고서는 공유해도 영수증이 노출되지 않습니다.

## B. 수동 표본 입력

## 표본 준비

1. 판매처, 길이, 조명, 구김, 글꼴이 다른 실제 영수증 표본을 정합니다.
2. 각 표본에 익명 ID를 부여합니다. 판매처 주소, 전화번호, 카드/승인/거래번호는 평가본에서 마스킹합니다.
3. 원문을 사람이 직접 전사하고 판매처, 날짜, 최종 합계, 상품 행, 판매처 SKU의 정답을 만듭니다.
4. 동일한 기기·앱 버전·촬영 조건을 기록합니다.
5. 앱의 “실제 기기 정확도 평가” 화면에 한 표본씩 입력합니다. 화면을 나가면 입력은 폐기됩니다.

## 지표 정의

- 문서 경계 자동 검출 성공률 = 자동 검출 성공 표본 / 전체 표본
- 수동 경계 수정률 = 수동 수정 표본 / 전체 표본
- OCR Character Error Rate = 전체 Levenshtein edit 수 / 전체 정답 문자 수
- 판매처명·날짜·최종 합계 정확도 = 정답이 존재하는 표본 중 exact match 비율
- 상품 행 precision = 일치 행 / 파싱 행
- 상품 행 recall = 일치 행 / 정답 행
- 상품코드 정확도 = 일치 SKU / 정답 SKU
- 합계 reconciliation 성공률 = 행 net 합계와 최종 합계가 일치한 표본 / 전체 표본
- 한 영수증 처리 시간 = 스캔 완료부터 OCR 초안 생성까지의 ms 평균
- 사용자 수정 필드 수 = 검수 수정 이력의 표본당 평균
- 차액 후보 precision = 원본 인쇄값과 일치한 1순위 후보 / 후보가 제시된 표본. 앱은 이 값을 계산하지 않으므로 평가 기록에 직접 남깁니다.

차액 후보 precision이 낮으면 후보를 늘리지 말고 근거 규칙을 좁힙니다. 틀린 후보를 적용하면 사용자가 원본과 다른 값을 확정할 수 있으므로, 이 지표는 "후보를 몇 개 보여줬는가"보다 우선합니다.

분모가 0인 지표는 100%가 아니라 `N/A`입니다. CER은 정답 전체 텍스트가 빈 표본을 분모에 넣지 않습니다. 행 precision/recall은 표본별 비율을 평균내지 않고 전체 count를 합산한 micro-average입니다.

## 보고 형식

보고서에는 다음을 함께 기록합니다.

- 앱 commit 또는 APK SHA-256
- Android 기기 모델과 OS 버전
- 표본 수와 포함/제외 기준
- ML Kit scanner 구성요소가 준비된 상태인지
- 각 지표의 분자와 분모
- 실패 유형 예시의 익명화된 분류
- raw 이미지와 전사 정답의 비공개 보관/삭제 정책

표본 수, 조건, 분모 없이 “vFlat 수준”, “높은 정확도”, “실사용 검증 완료”라고 표현하지 않습니다.
