# Windows OCR 검수자 UX 개선 및 재평가

평가일: 2026-10-23. 기준 커밋: `2a1fee44894636faeb198468df0d7bacd40c0e55`.
대상: `desktop-app`의 실제 Compose 검수 화면과 컨트롤러. Android, Core 계약 및 서버 API는 변경하지 않았다.

다음 두 스킬의 오류 예방, 입력 보존, 정보 위계, 점진적 상세 공개, 포커스 및 화면 적응 원칙을 Windows 반복 검수 업무에 적용했다.

- [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill), 확인한 소스 `623a9a9037d006ea727f8213f084d02a6b6f11b5`.
- [Mobile Design](https://github.com/RubenGlez/mobile-design), 확인한 소스 `97474ed9b969d0c7f8a2acf712e30eeb0b9078d1`. 휴대폰 고유 safe-area·터치 전용 배치 규칙은 Windows 평가에서 제외했다.

점수는 스킬의 공식 점수가 아니라 이전 감사와 동일한 가중치를 적용한 휴리스틱 잠정 평가다. 사용자 연구, SUS 또는 실사용 작업 시간 측정 결과가 아니다.

## 적용 사항

### P1: 화면의 수정값과 확정한 정본이 달라지는 문제

이전에는 상품명을 입력하고 적용하지 않은 상태에서 검수를 확정할 수 있었다. 화면에는 수정값이 남지만 확정된 정본은 이전 값이었다.

- 필드별 미적용 입력을 세션별 메모리 상태로 관리한다. 적용이 성공해야 해당 입력만 해제한다.
- 입력이 하나라도 남으면 검수 확정과 전송을 차단한다. 컨트롤러 직접 호출에도 같은 검사를 수행한다.
- 잘못된 숫자 등 검증 실패 시 입력을 보존한다. 다른 필드 적용이 남은 입력을 지우지 않는다.
- 원본 탭 및 로컬 문서 왕복 시 입력을 보존한다. 입력 취소는 정본 값으로 돌아간다.
- 새 구매 옵션 입력도 미적용 상태에 포함한다. 입력 중인 기존 옵션의 삭제 및 미적용 상태에서 실행 취소·다시 실행을 막는다.
- 실제 변경은 기존 Core 편집·검수 기록·번들 revision 보관 경로를 사용한다.

### P2: 우선순위와 반복 검수 동선

- 편집기를 기본으로 펼치고 충돌 해결을 먼저 배치한다. 일반 필드는 오류, 미적용 입력, 누락된 필수 값, 상품·영양 기준 순으로 정렬한다. 구매 옵션은 품목별 편집 그룹을 유지한다.
- 다음 확인 항목은 충돌 및 편집 필드로 스크롤하고 포커스를 이동한다. 입력 중인 새 옵션도 이동 대상이다.
- 상품 문서 요약은 상품명·브랜드·영양 기준을 보여준다. 날짜·금액은 구매/영수증 자료가 있는 경우에만 요약한다.
- 확정·전송 동작을 나란히 배치하고 고정 영역을 줄였다. 전송 최종 확인은 별도 대화상자로 제공한다.
- 개발자 정보는 더보기 메뉴의 별도 대화상자로 이동했다. 추출 결과 상세는 필요할 때 펼친다.
- 일반 완료 안내를 진행 중 배지로 표현하지 않는다.

## 검증

실행 명령:

```powershell
.\gradlew.bat :desktop-app:test :desktop-app:jar --offline --console=plain
git diff --check
```

결과: **64개 중 61개 통과, 기존 3개 건너뜀, 실패/오류 0개**, JAR 빌드 성공, diff 공백 검사 통과.

추가 회귀 테스트 8개:

- `DesktopReviewDraftTest`: 컨트롤러 확정/전송 차단, 잘못된 숫자 보존 및 독립 필드 적용, 정규화 무변경 적용 및 세션 왕복, 새 옵션 미적용 입력.
- `DesktopReviewerUxTest`: 실제 화면의 수정→적용→확정→재입력→전송 차단, 충돌 첫 화면 및 이동/해결, 최소 창의 버튼 노출 및 탭 왕복 보존, 잘못된 숫자의 이동/취소 복구.

UI 테스트는 실제 `YeonsikCollectorApp`과 실제 컨트롤러를 사용한다. 저장소 예제 데이터와 임시 세션 저장소, 인증 정보가 없는 설정으로 실행하며 외부 전송은 수행하지 않는다. 문자열 값만으로 필드를 선택하지 않고 필요한 경우 필드 경로를 기준으로 선택한다.

재현 가능한 테스트 캡처는 `desktop-app/build/reports/reviewer-ux/`에 생성된다:

- `after-1200-initial.png`
- `after-draft-blocked.png`
- `after-820-conflict.png`
- `after-820-conflict-resolved.png`
- `after-800-draft.png`

테스트 렌더러는 공개 `runDesktopComposeUiTest(width, height)` API로 실제 검증 크기를 설정한다. 기본 1024×768 캡처가 잘리는 중간 결과는 최종 평가 근거에서 제외했다.

## 남은 한계

- 이번 시각 증거는 Windows에서 실행한 Compose 테스트 렌더링이다. 설치된 배포 EXE 교체, 실제 Windows 창의 DPI/다중 모니터 검증, 스크린리더 검증은 수행하지 않았다.
- 원본 이미지의 필드별 위치 강조와 실제 이미지 대조 E2E, 서버 보관·전송 E2E는 검증하지 않았다.
- 미적용 입력은 앱 실행 중 세션별로 유지된다. 앱 종료/재시작을 넘는 초안 보존은 구현하지 않았다.
- 긴 다품목 문서의 실사용 처리 시간과 키보드 전용 작업 효율은 별도 사용자 검증이 필요하다. 이번 점수 상승을 처리 시간 단축률로 해석하지 않는다.
