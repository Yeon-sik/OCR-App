# Windows 검수 밀도·일괄 적용·드롭 영역 수정

검증일: 2026-10-23. 기준 커밋: `9adb73cf4fccf2d0eb3a061d5cdab81fed8f770e`.

## 변경 결과

- 검수 필드는 실제 편집 영역 너비에 따라 1~3열로 배치한다. 520dp 이상은 2열, 900dp 이상은 3열이다. 기존 Windows 1440×900 창의 중앙 검수 영역에서는 2열로 표시된다.
- 일반 필드마다 반복되던 적용 버튼과 필수/선택 행을 제거했다. 라벨은 입력칸에 유지하며, 값 지우기는 입력칸 안의 동작이다. enum은 긴 가로 버튼 목록 대신 선택 메뉴로 제공한다.
- 입력하는 동안 필드 순서는 고정한다. 오류·미적용 우선순위는 다음 확인 항목 이동에 사용하며, 타이핑할 때 항목을 맨 위로 옮기지 않는다.
- 상단의 변경 개수, 변경사항 모두 적용, 변경 취소로 여러 필드를 처리한다. 문자열·숫자·enum 변경과 아직 추가하지 않은 새 옵션 입력을 함께 적용할 수 있다. 충돌 값 채택과 옵션 삭제/재정렬은 별도의 명시적 구조 편집 동작을 유지한다.
- 일괄 적용은 타입과 범위를 먼저 확인하고 최종 문서를 검증한다. 실패하면 정본·변경 기록을 부분 저장하지 않고 입력을 보존한다. 수량/단가/순금액 및 구매 합계처럼 상호 제약이 있는 값은 같은 객체에서 함께 갱신한다.
- 성공한 묶음은 기존 revision 보관 경로로 한 번 전달되며, 하나의 실행 취소 체크포인트를 만든다. 정본 변경 후 재검수가 필요하다는 기존 규칙을 유지한다.
- 파일 드롭 영역에서 투명 SwingPanel을 제거했다. 글자 위에 별도 네이티브 패널이 겹치는 구조를 없애고, Compose의 드롭 이벤트로 파일 목록을 받는다. 여러 파일과 비활성 상태 처리를 유지한다. [Compose 드롭 API 문서](https://kotlinlang.org/docs/multiplatform/compose-drag-drop.html).
