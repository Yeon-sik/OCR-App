# 알려진 제한사항

- 현재 소스 버전은 `0.2.0`이며 공통 OCR 세션, PriceTrace/Fitness 홈 탭, 영양 라벨 파서, Fitness 직접 DB adapter와 기존 Gemini 흐름을 로컬 테스트/컴파일했습니다. 이 APK를 기기에 설치하거나 실제 Gemini/Nutrition 네트워크로 검증하지 않았습니다.
- `0.1.14` debug APK는 `SM-A256N`에 업데이트 설치되어 패키지 버전과 `MainActivity` 실행 상태를 확인했습니다. 안내·결제 문장의 상품 오인식을 차단하고, 주소를 첫 지역 토큰부터 잘라내며, 상품명 셀의 후행 숫자를 숫자 열로 분리합니다. OCR metadata 순서가 뒤섞인 헤더에서 판매처 후보를 복구하고 브랜드 옆 연도 슬로건을 제외합니다. 합성 회귀 테스트를 통과했지만 이 버전의 실제 영수증 재검증은 남아 있습니다.
- Gemini 교정은 선택 기능입니다. 앱 화면에서 유효한 API 키를 저장하기 전에도 기존 로컬 OCR은 동작하지만 AI 요청은 비활성화됩니다.
- API 키는 Android Keystore로 암호화해 기기에 저장하지만 직접 API를 호출하는 모바일 앱에서는 추출 불가능한 production secret으로 간주할 수 없습니다. 현재 구현은 개인 사용 경계이며 공개 배포 전에 backend proxy로 교체해야 합니다.
- 교정 요청은 기존 OCR 상품 행 최대 12개와 근거 crop 최대 8개로 제한되므로, OCR이 완전히 놓친 상품 행이나 판매처·주소·합계 필드는 복원하지 않습니다. 사용자가 직접 추가한 행도 AI 요청에서 제외합니다.
- 사업자번호·전화·카드·거래번호·주소 형태의 OCR line을 전송 전 제외하지만 이는 보수적 휴리스틱입니다. 민감정보를 완전히 탐지한다고 보장하지 않으므로 실제 기기에서 crop 범위를 확인하고, 고위험 영수증에는 무료 tier 요청을 사용하지 않아야 합니다.
- 구조화 응답, source line 검증과 산술 보존식은 근거 없는 제안을 줄이는 방어선일 뿐 정확성을 보장하지 않습니다. 통과한 제안도 낮은 신뢰도로 저장되며 원본 대조와 최종 사용자 검수가 필요합니다.
- Gemini Developer API 무료 tier의 가용성·rate limit·데이터 사용 조건은 외부 정책에 의존합니다. 실제 영수증 사용 전 현재 조건과 API quota를 다시 확인해야 하며, 인증·한도·네트워크·provider·유효하지 않은 응답은 제안 없음으로 처리됩니다.
- ML Kit Document Scanner는 Google Play Services 지원 여부와 최초 구성요소 다운로드에 의존합니다.
- OCR 정확도는 실제 영수증 표본에서 측정하지 않았습니다. confidence API가 검증되지 않은 ML Kit 항목은 `null`로 보존합니다.
- `generic-parser.v15`은 구역별 후보 우선순위, 안내문 경계 제외, 이름 블록의 글자 크기·공간 점수, metadata 행 뒤 인접 판매처 후보 복구, 지역 토큰 기반 주소 시작점, 상품명/단가/수량/금액의 x좌표 경계, 복합·분절 숫자 요소 복원을 사용합니다. 판매처별 복잡한 다단 레이아웃을 모두 처리하지 못하며, 경계가 불명확할 때는 상단 16행·하단 14행 fallback을 사용합니다.
- 이전 파서로 저장된 검수 세션은 사용자 수정 내용을 보호하기 위해 자동 재파싱하지 않습니다. 복원 안내 후 이미지 확인 화면에서 OCR을 다시 시작해야 새 규칙이 적용됩니다.
- 단가가 인쇄되지 않은 상품 행은 단가를 역산하지 않고 `null`로 둡니다. 명시적 단가가 있는 경우에만 `수량 × 단가 = 행 금액` 보존식을 검사합니다.
- 수량 셀이 OCR에서 사라진 경우의 계산 복원은 명시적인 단가·수량·금액 열과 정확한 1~100 정수 비율에 한정합니다. 할인·중량·반올림 등으로 식이 맞지 않으면 수량을 추측하지 않고 `null`로 둡니다.
- 상품명 한 글자 보정은 무제한 맞춤법 교정이 아니라 검증된 전체 단어 힌트의 유일한 편집거리 1 후보에만 적용합니다. 현재 힌트는 요청 표본의 `제스프리골드`처럼 제한적이며, 원 OCR 문자열은 provenance에 유지됩니다.
- 시간대가 인쇄되지 않은 구매 현지시각은 `purchase_local_time=HH:mm:ss` note로 보존합니다. 근거 없이 `receipt.v2 document.issued_at` offset을 생성하지 않습니다.
- 영수증을 판매처 상품 또는 PriceTrace 표준 상품에 자동 연결하지 않습니다.
- 하나의 촬영 결과 페이지 byte를 메모리에 읽은 뒤 앱 전용 파일로 복사하므로 매우 큰/많은 페이지에서는 메모리 압력이 생길 수 있습니다.
- 이미지 미리보기는 sampled bitmap을 사용합니다. 극단적으로 긴 이미지에서 bounding box 시각 정렬은 실제 기기 QA가 필요합니다.
- 검수 입력은 변경 시마다 앱 전용 draft와 Room 수정 이력에 저장합니다. 대량 입력 debounce는 없습니다.
- 되돌리기·다시 적용은 앱을 실행 중인 동안에만 유지되는 메모리 스택(최대 50단계)입니다. 세션을 다시 불러오면 수정 이력은 남지만 되돌리기 스택은 비어 있습니다.
- 차액 원인 후보는 초안에 이미 있는 숫자만으로 세운 가설이며 정답이 아닙니다. 여러 행이 동시에 잘못 인식되었거나 차액이 어떤 단일 행으로도 설명되지 않으면 "누락된 행" 같은 일반 안내만 제시합니다. 숫자 혼동 규칙은 감열지 표본에서 관찰한 짝(0·6·8·9, 1·4·7, 2·3·7, 3·8·9, 4·9, 5·6·8)에 한정하며 정량 측정으로 검증하지 않았습니다.
- 사용자가 직접 추가한 행은 OCR 근거가 없으므로 `user_entered:` 표식과 경고로만 구분합니다. 이 행의 정확성은 사용자의 대조에 전적으로 의존하며 앱이 검증할 방법이 없습니다.
- 행 추가·삭제와 되돌리기의 실기기 UI 동작은 계측 테스트 컴파일까지만 확인했고 에뮬레이터·실기기 실행으로 검증하지 않았습니다.
- raw OCR 포함 여부에 따라 외부 JSON revision이 달라집니다. 기본값은 제외입니다.
- 화면 캡처 제한, 저장 파일 자체 암호화, biometric gate는 구현하지 않았습니다.
- 수동 표본 입력 데이터는 메모리에만 있으며 화면을 벗어나면 폐기됩니다.
- 검수 이력 기반 필드 오류율은 사용자가 발견한 오류만 셉니다. 놓친 오류는 정답으로 집계되므로 실제 오류율의 하한입니다.
- 검수 소요 시간은 OCR 초안 생성부터 확정까지의 경과 시간이며, 앱을 닫아두거나 중간에 다른 일을 한 시간이 포함됩니다. 순수 작업 시간이 아닙니다.
- `ocr_completed_at` 컬럼은 v2→v3 migration으로 추가되었습니다. 그 이전에 확정한 세션은 값이 없어 소요 시간 통계에서 제외됩니다.
- 정확도 보고서는 건수·비율만 담지만, 표본 수가 매우 적으면 비율 자체가 특정 영수증을 암시할 수 있습니다.
- PriceTrace 영수증 업로드는 구현하지 않았습니다. Fitness Nutrition 로그인·private insert/update adapter는 구현했지만 실제 URL·계정·RLS·migration으로 실행하지 않았습니다.
- Fitness 영양 라벨 파서는 명시적인 영양소명 뒤의 `kcal`, `g`, `mg` 값과 명시적 `1회 제공량`/`100g당`/`100ml당` 기준만 보수적으로 읽습니다. 여러 값이 경쟁하면 자동 선택하지 않으며 상품명·분류·기준량·필수 7종은 사용자가 확인해야 합니다.
- Fitness 원격 실패의 로컬 초안은 보존하지만 WorkManager 기반 자동 retry queue는 없습니다. 같은 세션을 열어 사용자가 다시 저장해야 합니다.
- Fitness 전송은 `ocr-nutrition:<document-id>` 단위로 멱등 재시도하고 revision 충돌을 차단합니다. 같은 실물 상품을 다른 세션에서 다시 촬영한 결과를 자동 병합하지 않습니다.
- release 배포, 서명, Play Console 정책 검증을 수행하지 않았습니다.
